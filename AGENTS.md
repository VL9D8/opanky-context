# Repository rules

1. Read `CONTEXT.md`, `context.json`, and the relevant canonical document before changing state.
2. Treat owning project repositories and verified behavior as authoritative for code/runtime claims.
3. Never publish secrets, contacts, raw chats, private paths, confidential briefs, or unpublished assets.
4. Keep canonical context English-only and label uncertainty explicitly.
5. Edit `context.json`, then run the renderer; never hand-edit generated views.
6. Update architecture, current state, decisions, and roadmap in the same change when their facts change.
7. Prefer mature primitives to custom code and keep validation deterministic.
8. Run repository validation before commit; do not bypass failed checks.
9. Ask the owner before publishing private material, changing direction, licensing content, changing access, or taking costly, destructive, or legal actions.
